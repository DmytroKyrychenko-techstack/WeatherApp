# Weather App — New Features (2026-06-28)

## Overview

Four interconnected features added to demonstrate React hooks (`useReducer`, `useMemo`, `useCallback`, `useRef`), TypeScript best practices (discriminated unions, proper nullability, union types), and SOLID principles.

## Feature A: Temperature Unit Toggle (C° / F°)

### What's New
- Global temperature unit switcher in the Navbar
- All temperature displays across the app (home, details, favorites, hourly, daily) respect the selected unit
- Toggle button shows current unit with thermometer icon

### Implementation Details

**Files Created:**
- `src/lib/temperature.ts` — Pure conversion utilities (`toFahrenheit`, `toCelsius`, `convertTemp`, `formatTemp`)
- `src/hooks/use-temperature-unit.ts` — `useReducer`-based hook managing unit state
- `src/context/temperature-unit-context.tsx` — Context provider wrapping the app

**Files Modified:**
- `src/app/providers.tsx` — Wrapped with `TemperatureUnitProvider`
- `src/components/layout/navbar.tsx` — Added toggle button with `useCallback` handler
- `src/components/weather/current-weather.tsx` — `useMemo` for temperature conversion
- `src/components/weather/weather-card-parts.tsx` — `WeatherHeroRow` uses context + `useMemo`
- `src/components/weather/forecast-card.tsx` — `useMemo` for min/max temps
- `src/components/weather/hourly-forecast.tsx` — `useMemo` for hourly temps
- `src/components/weather/weather-detail-hero.tsx` — `useMemo` for 10 stats with temp conversions
- `src/components/favorites/favorite-city-card.tsx` — `useMemo` for displayed temp

**React Hooks Demonstrated:**
- `useReducer` with discriminated union actions (`SET_UNIT | TOGGLE`)
- `useMemo` for temperature conversions (avoids recalculating on every render)
- `useCallback` for toggle handler passed to Navbar button
- Context API for global state

**TypeScript Patterns:**
```typescript
type TemperatureUnit = "celsius" | "fahrenheit";
type TemperatureUnitAction =
  | { type: "SET_UNIT"; unit: TemperatureUnit }
  | { type: "TOGGLE" };
```

**SOLID Principles:**
- **Single Responsibility:** `temperature.ts` contains only conversion logic
- **Open/Closed:** Adding Kelvin later only adds a new case, never modifies existing
- **Interface Segregation:** Components receive only `unit: TemperatureUnit`, not full context
- **Dependency Inversion:** Display components depend on abstraction, not hardcoded Celsius

## Feature B: Search Bar State Consolidation

### What's New
- Refactored SearchBar from 3 `useState` calls to single `useReducer`
- Maintains proven `useDebounce` hook (don't reinvent working patterns)
- Keyboard navigation with arrow keys, Enter, and Escape
- Dropdown shows recent search history when input is empty/short, autocomplete results when typing

### Implementation Details

**Files Modified:**
- `src/components/weather/search-bar.tsx` — State management consolidated to `useReducer`

**React Hooks Demonstrated:**
- `useReducer` with discriminated union actions (consolidates 3 `useState` calls):
  ```typescript
  type SearchBarAction =
    | { type: "SET_INPUT"; value: string }
    | { type: "OPEN_DROPDOWN" }
    | { type: "CLOSE_DROPDOWN" }
    | { type: "SET_HIGHLIGHT"; index: number }
    | { type: "INCREMENT_HIGHLIGHT"; max: number }
    | { type: "DECREMENT_HIGHLIGHT"; max: number }
    | { type: "RESET" };
  ```
- `useRef<HTMLInputElement>` — Input element reference for blur/focus
- `useDebounce(state.inputValue)` — Proven debouncing hook (reusable, testable)
- `useCallback` for handlers: `closeDropdown`, `selectCity`, `selectHistoryItem`

**SOLID Principles:**
- **Single Responsibility:** `searchReducer` pure function handles only state transitions
- **Interface Segregation:** Sub-components (`HistoryDropdown`, `AutocompleteDropdown`) receive only needed props
- **Open/Closed:** Easy to add new actions without modifying reducer logic

**Key Pattern:**
Shows how to use `useReducer` for related state (input, dropdown visibility, highlight index) while keeping other concerns separate (debouncing via hook, async search via TanStack Query)

**React Hooks Demonstrated:**
- `useReducer` with discriminated union actions:
  ```typescript

    | { type: "SET_SORT"; field: SortField }
    | { type: "TOGGLE_DIRECTION" }
    | { type: "SET_FILTER"; value: string }
  ```

- **Single Responsibility:** `useFavoritesView` manages only view state (sort + filter)
- **Open/Closed:** Adding "sort by temperature" only adds new `SortField` literal + comparator
- **Interface Segregation:** Sort controls receive only `{ state, onSort, onFilter }`

## Feature D: Weather Statistics Panel

### What's New
- New section on city detail page showing computed insights from 3-day forecast
- Displays:
  - **Temperature Range** across all 3 days (in user's selected unit)
  - **Average Humidity** across 3 days
  - **Peak UV Index Time** (hour with highest UV)
  - **Rain Probability Trend** (rising / stable / falling) with badge color-coding
- Pure computation, zero side effects
- Seamlessly integrated with temperature unit toggle

### Implementation Details

**Files Created:**
- `src/lib/weather-stats.ts` — Pure function `computeWeatherStats(forecastDays)` returning `WeatherStatsSummary`
- `src/components/weather/weather-stats-panel.tsx` — Display component with trend visualization

**Files Modified:**
- `src/app/weather/[city]/page.tsx` — Added `WeatherStatsPanel` between forecast grid and astronomy card

**React Hooks Demonstrated:**
- `useMemo` for all 4 computed values:
  - Temp range min/max with conversion (respects unit toggle)
  - Average humidity calculation
  - Peak UV hour scan
  - Rain trend analysis (compares first half vs second half of forecast)
- `useCallback` for trend label formatting (pure display logic)
- Uses `useTemperatureUnitContext` to convert temps on-the-fly

**TypeScript Patterns:**
```typescript
type TrendDirection = "rising" | "stable" | "falling";
interface WeatherStatsSummary {
  tempRangeC: { min: number; max: number };
  avgHumidity: number;
  peakUvHour: string;
  rainTrend: TrendDirection;
}
```

**SOLID Principles:**
- **Single Responsibility:** `computeWeatherStats` computes only; component renders only
- **Liskov Substitution:** `WeatherStatsSummary` props shape identical across all uses
- **Dependency Inversion:** Panel receives pre-computed `stats`, not raw `ForecastDay[]`

**Algorithm Notes:**
- Rain trend: Compares average rain chance in first half vs second half of 3-day period
  - If avg second half > avg first half + 5%: "rising"
  - If avg first half > avg second half + 5%: "falling"
  - Otherwise: "stable"

## TypeScript Best Practices Across All Features

| Pattern | Usage | Benefit |
|---------|-------|---------|
| Discriminated unions | All 4 reducer action types | Type-safe state transitions, exhaustiveness checking |
| Union types | `TemperatureUnit`, `SortField`, `TrendDirection` | Strict literal types, prevents invalid values |
| Proper nullable typing | `data \| null`, `string \| null` | Explicit null handling, no accidental undefined bugs |
| Optional chaining | `data?.current.temp_c` | Safe property access without guard clauses |
| `as const` | Action type literals | Type narrowing, literal type inference |
| Explicit component props | All new components | Clear contracts, self-documenting |

## Key Learnings

### React Hooks Mastery
- `useReducer` scales better than multiple `useState` for complex state
- `useMemo` critical for expensive computations (conversions, sorting, filtering)
- `useCallback` required when deps are refs or when passing handlers to memoized children
- `useRef` has two roles: side-effect-free (timers, DOM) vs render-time access (state)

### TypeScript Strictness
- Discriminated unions catch more errors at compile time than ad-hoc unions
- Explicit nullable types prevent silent failures
- `as const` enables literal type inference for action dispatch safety

### SOLID in React
- Single Responsibility: Each hook/util has one job
- Open/Closed: New units/sort fields extend without modifying existing code
- Liskov Substitution: Components swap implementations without changing behavior
- Interface Segregation: Props interfaces list only what's needed
- Dependency Inversion: Components depend on abstractions (context, types), not concrete implementations
