### Infrastructure

#### **docker-compose.test.yml**
- PostgreSQL 18 Alpine image
- Container: `weatherapp-db-test` on port 5434
- tmpfs (in-memory storage) — auto-cleaned on `docker compose down -v`
- Healthcheck via `pg_isready`

#### **scripts/test-integration.mjs**
Node.js ESM runner that orchestrates:
1. Docker container startup (`docker compose up -d --wait`)
2. Prisma migrations (`prisma migrate deploy`)
3. Vitest execution with isolated env vars
4. Container + volume cleanup (even on test failure)

Environment injection:
```
DATABASE_URL=postgresql://weatherapp_test:weatherapp_test@localhost:5434/weatherapp_test
JWT_SECRET=integration-test-jwt-secret-minimum-32-chars!
WEATHER_API_KEY=test-only-not-used
```

#### **vitest.integration.ts**
- Environment: `node` (not jsdom)
- Pattern: `src/integration/**/*.integration.test.ts`
- Globals enabled
- Setup: `src/integration/setup.ts` (truncates tables before each test)
- Teardown: `src/integration/global-setup.ts` (closes Prisma on suite exit)
- Single-threaded mode (`threads: false`)

#### **src/integration/** Support Files
- **setup.ts** — `beforeEach` hook truncates users, favorites, history tables
- **global-setup.ts** — `teardown()` export closes Prisma connection pool
- **helpers.ts** — `createTestUser()`, `makeAuthRequest()` utilities

#### **.github/workflows/integration-tests.yml**
CI/CD job (runs on push/PR to master):
```yaml
- Checkout
- Setup pnpm 10 + Node 24
- Install dependencies (frozen lockfile)
- Prisma generate
- pnpm test:integration
  env: WEATHER_API_KEY=test-only-not-used
```

Single job (not split) — 14 tests complete in ~3s.

## Planned: E2E Test Suite

### Why E2E Instead of Integration?
1. **Server Actions** (login/logout) require Next.js `cookies()` + `redirect()` → Full server context
2. **Protected pages** (`/favorites`, `/weather`) → Route guards, redirects → Browser simulation
3. **Search with WeatherAPI** → External API dependency, rate limiting → Test isolation
4. **Form validation UX** → Client-side Zod errors, visual feedback → DOM interaction

### Planned Test Cases (E2E with Playwright)

#### Authentication
- [ ] Register new user with valid email/password
- [ ] Register fails with duplicate email
- [ ] Register fails with weak password
- [ ] Login with valid credentials
- [ ] Login fails with invalid email/password
- [ ] Unauthenticated users redirected from `/favorites` to `/login`
- [ ] Unauthenticated users redirected from `/weather/[city]` to `/login`
- [ ] Logout clears cookie + redirects to `/login`
- [ ] JWT expiration (7 days) → redirect to login

#### Favorites Page
- [ ] Add city to favorites from `/weather/[city]`
- [ ] Favorites page displays only current user's items
- [ ] Remove favorite from `/favorites` page
- [ ] Favorite icon toggles visual state (filled/unfilled)
- [ ] Cannot favorite duplicate city (show toast error)

#### Search
- [ ] Search by city name returns results
- [ ] Nonexistent city shows "no results" message
- [ ] Search history populated on city selection
- [ ] Search history displays last 5 searches
- [ ] Can clear individual search history items

#### Cross-User Isolation
- [ ] User A's favorites not visible to User B
- [ ] User A's search history not visible to User B
- [ ] Switching accounts shows correct data per user

### Tooling
- **Framework:** Playwright (cross-browser: Chromium, Firefox, WebKit)
- **CI:** `.github/workflows/e2e-tests.yml` (separate from integration tests)
- **Baseline:** Pages must load in <3s, favorites/search respond in <500ms
- **Fixtures:** Pre-created test users, test database seeding
